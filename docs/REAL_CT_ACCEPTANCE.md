# Public individual-CT entry acceptance

This runner exercises the complete file-to-exact-path software flow on **one
public individual CT**. It does not use a synthetic volume or an averaged
atlas. It is not clinical validation and must never be described as evidence
that an entry or path is safe.

## Required inputs

Provide one paired NasalSeg image and manual label volume plus one directory
containing Azure-produced TotalSegmentator NIfTI masks from both tasks:

- `craniofacial_structures`
- `headneck_bones_vessels`

The image and manual label must already be paired and physically aligned.
NIfTI and NRRD are accepted. If a file omits spatial units, the runner's
explicit assumption is millimetres and this remains visible in the provenance.
The fixed NasalSeg manual mapping is:

1. right maxillary sinus
2. left maxillary sinus
3. right nasal cavity
4. left nasal cavity
5. nasopharynx

The TotalSegmentator directory is searched recursively, so task-specific
subdirectories are allowed. Recognized bone/maxilla-related outputs are
conservatively unioned. Recognized left and right internal carotid outputs are
also unioned. These model outputs remain marked **predicted**, not reviewed.

## Run

Use a new or empty output directory:

```bash
python research/run_real_ct_entry_acceptance.py \
  --ct /path/to/P001_img.nrrd \
  --manual-label /path/to/P001_seg.nrrd \
  --totalsegmentator-dir /path/to/azure-output \
  --output /path/to/acceptance-P001 \
  --case-id NasalSeg-v2-P001-public-individual
```

The default declared computational model is a 200 mm long, 1 mm radius rigid
shaft through a 4 mm radius portal. These are replay parameters, not an
instrument recommendation. Relevant parameters can be overridden on the
command line and are recorded in `request.json` and `report.json`.

The target is not a tumor. It is one deterministic interior voxel from manual
nasopharynx label 5: the runner intersects the posterior 35% (low RAS Y) and
superior 35% (high RAS Z), then selects maximum physical interior distance
with declared deterministic tie breaks. This computational landmark exists
only to make the acceptance replay target-driven and reproducible.

## Processing and interpretation

The runner:

1. loads the real image and manual label into common RAS XYZ millimetres;
2. nearest-neighbour resamples predicted masks onto that grid when needed
   (resampling is not registration);
3. writes each common-grid mask as Slicer-loadable NIfTI;
4. calls `propose_entry_candidates`;
5. creates one `CorridorCase` and one exact finite path per proposal, with
   explicit instrument length/radius, portal disk and angular constraint;
6. calls `evaluate_exact_paths`; and
7. writes the replay request, cases, report, timings, provenance and SHA-256
   manifests.

No virtual bone removal is authorized. Consequently, a centerline crossing the
conservative bone union is reported as blocked under the declared model.
Available ICA masks are collision constraints, but they are predictions and
do not make anatomy complete.

Missing ICA sides, missing bone/maxilla constraints, and critical structures
not represented by these two TotalSegmentator tasks are retained as unknown
`ProtectedStructure` records. Exact evaluation therefore returns
`unavailable` where incomplete anatomy controls the result. A `blocked` result
only identifies a collision under declared masks. A `conditional` or
`unavailable` result identifies unresolved knowledge. Even
`model_feasible`—which this acceptance setup should not produce while required
unknown structures are retained—would mean only model feasibility, never
safety.

## Output contract

The output directory contains:

- `report.json`: proposal output, exact-path states, limitations, provenance,
  observational stage timings and artifact references;
- `request.json`: canonical replay inputs, hashes and parameters;
- `sha256-manifest.json`: hashes for generated replay artifacts;
- `cases/*.json`: exact `CorridorCase` and path candidate for each proposal;
- `target_landmark_NOT_TUMOR.nii.gz`;
- common-grid NasalSeg masks, plus available predicted bone, ICA union and
  optional constraint masks as `.nii.gz`.

Input files and every TotalSegmentator mask actually consumed are SHA-256
hashed. Generated NIfTI and JSON artifacts are also hashed. Stage timings are
observational machine-dependent metadata and are deliberately excluded from
the replay hash.

Keep the public dataset's attribution, license, and any Azure export metadata
with the run. The runner records paths and hashes but cannot prove that a local
file was lawfully obtained, de-identified, manually reviewed, or generated by
the declared upstream model version.

## Acceptance review

Before treating the run as passed, independently verify:

- the input is an individual public subject, not an atlas or transformed
  cohort average;
- all five manual labels have the declared left/right semantics;
- CT, labels and generated masks align in Slicer in all three planes;
- both requested TotalSegmentator tasks were exported and their model/version
  provenance is retained externally;
- unavailable ICA or other constraints remain explicitly unavailable;
- every proposed portal, internal medial-wall landmark and path is visibly
  traceable to the source image; and
- no report, screenshot, or downstream summary calls any result safe.

Automated tests use tiny synthetic arrays only to verify mechanics. They are
not a substitute for executing this runner with public real files.

## Executed P001 evidence — 2026-10-07

The workflow was executed on the checksum-verified NasalSeg v2 P001 individual
CT (`153 × 205 × 52`, approximately `0.586 × 0.586 × 1.5 mm`). Azure CPU
inference used TotalSegmentator 2.11.0 on `Standard_D4as_v7`.

- Cold task timings: craniofacial 111.322 s; head/neck vessels 20.809 s.
- Cached-weight task timings: craniofacial 93.929 s; head/neck vessels
  20.800 s; combined 114.729 s.
- Local common-grid preparation: 0.261 s.
- Target-driven proposals: 0.080 s.
- Six exact finite-path evaluations: 1.277 s.
- Input loading/validation and Slicer-mask writing: 4.812 s.

The run generated four EEA candidates and two contralateral CTM candidates.
Exact evaluation returned three `blocked` and three `unavailable` states.
No candidate was labeled model-feasible because predicted obstacles were
honored and unmodeled optic, cavernous-sinus, cranial-nerve and ophthalmic
artery anatomy remained unknown.

Native Slicer 5.12.4 then loaded the individual CT and generated NIfTI masks,
rendered one EEA and one CTM candidate using the exact recorded entry and
target coordinates, displayed their separate entry windows and shafts in the
slice/3D views, and saved:

- `research/results/real-ct-p001-acceptance/workflow/report.json`
- `research/results/real-ct-p001-acceptance/slicer/real-ct-target-paths.mrb`
- `research/results/real-ct-p001-acceptance/slicer/real-ct-target-paths.png`
- `research/results/real-ct-p001-acceptance/slicer/verification.json`

The cached model tasks plus measured local stages total approximately 121.1 s,
before queue and transfer overhead. This is a measured near-miss of the
provisional 120 s cloud-to-review goal, not a pass. Proposal generation plus
all six local exact-path evaluations took approximately 1.36 s, slightly above
the provisional 1 s cached target-edit goal on the test machine. No operator
effort or anatomical-quality claim is made from this single software replay.
